# Project: Harness-Dev

## Directory Overview
이 프로젝트는 AI 코딩 어시스턴트(Integrated AI Coding Assistant)를 위한 전문적인 방법론과 하네스(Harness) 설정을 포함하고 있습니다. 주요 목적은 AI가 복잡한 소프트웨어 엔지니어링 과업을 수행할 때 일관된 페르소나를 유지하고, 체계적인 SDLC(소프트웨어 개발 생명주기) 프로세스를 따르도록 안내하는 것입니다.

### Structure
- **harness/**: 영문으로 작성된 핵심 방법론 및 스킬 정의 파일들이 포함되어 있습니다.
- **harness-ko/**: `harness/` 디렉토리의 내용을 한국어로 번역한 버전입니다.
- **hypercortex/** (참조 전용): 프로젝트 수행 시 생성되는 지식 그래프 및 영구 메모리 저장소입니다. (현재 루트에는 존재하지 않으며, 실제 작업 시 `workspace/`와 함께 운용됩니다.)

## Key Files

### Personas (`harness/PERSONA.md`, `harness-ko/PERSONA.md`)
AI 어시스턴트가 상황에 따라 전환해야 할 5가지 핵심 페르소나를 정의합니다:
1.  **수석 시스템 아키텍트 (Principal System Architect)**: 전체 시스템 설계 및 아키텍처 비전 담당.
2.  **마스터 소프트웨어 개발자 (Master Software Developer)**: 고성능, 메모리 안전 및 정밀 수정(Surgical Principle) 코드 구현 담당.
3.  **수석 리뷰어 (Principal Reviewer)**: 보안 감사 및 아키텍처 정렬 검증 담당.
4.  **수석 테스트 엔지니어 (SDET)**: 시스템 한계 검증 및 자동화 테스트 구축 담당.
5.  **수석 프론트엔드 엔지니어 및 UX/UI 디자이너 (Principal Frontend Engineer & UX/UI Designer)**: 사용자 경험 설계, 웹 접근성(a11y) 및 i18n 전담 구현 담당.

### Workflow (`harness/WORKFLOW.md`, `harness-ko/WORKFLOW.md`)
다음의 6단계 SDLC 프로세스를 강제하며, 각 단계마다 **지속적 검증(Continuous Validation)**을 수행합니다:
1.  **[PHASE 1] 요구 사항 분석**: 아키텍트가 문제 정의 및 제약 조건 식별. (리뷰어 검증 필수)
2.  **[PHASE 2] 설계**: 아키텍트와 프론트엔드 엔지니어가 기술 전략, UI/UX 및 아키텍처 제안. (리뷰어 검증 필수)
3.  **[PHASE 3] 사양 정의**: 아키텍트, 개발자 및 프론트엔드 엔지니어가 인터페이스 및 데이터 흐름 정의. (리뷰어 검증 필수)
4.  **[PHASE 4] 개발**: 개발자와 프론트엔드 엔지니어가 `workspace/` 내에 방어적 코드 및 UI 구현. (자체 리뷰 필수)
5.  **[PHASE 5] 심층 코드 및 보안 감사**: 리뷰어가 코드의 보안 취약점, 성능 병목 구간, 설계 정렬 상태를 심층 검증 및 분석.
6.  **[PHASE 6] 테스트**: SDET가 격리된 자동화 테스트 구축 및 검증.

- **예외 (Fast-Track)**: 단순 버그 수정이나 아키텍처 변경이 없는 소규모 작업의 경우, 1~3단계를 생략하고 곧바로 4단계(개발)부터 시작할 수 있습니다.

## Usage
이 프로젝트의 가이드를 따르기 위해서는 다음 원칙을 준수해야 합니다:

1.  **지속적 검증 및 입체적 피드백 루프 (Shift-Left & 3-Tier Feedback Loop)**:
    - **상위 루프**: 1~3단계 기획/설계 시 아키텍트와 리뷰어 간의 반복 검증.
    - **실행 루프**: 4~6단계 개발/리뷰/테스트 간의 초단기 반복 최적화.
    - **메타 루프**: 작업 종료 후 교훈을 자산화하여 다음 작업의 1단계에 반영.
    - 결함 발견 시 근본 원인이 있는 상위 단계로 즉시 회귀하여 문서를 수정해야 합니다.
2.  **지식 추적성 (Traceability)**: 모든 아키텍처 결정과 기술적 결정은 `hypercortex/` 내의 문서 간 상호 참조를 통해 추적 가능해야 합니다.
3.  **워크스페이스 격리 (Isolation)**: 모든 실제 구현(코드, 테스트, 빌드 자산)은 반드시 `workspace/` 디렉토리 내에 위치해야 합니다.
4.  **하이퍼코텍스 업데이트**: 각 SDLC 단계 완료 후 관련 지식을 하이퍼코텍스에 업데이트하여 영구적인 컨텍스트를 유지합니다.
5.  **국제화 (i18n)**: 모든 사용자 대상 텍스트와 UI 구성 요소는 국제화를 고려하여 설계 및 구현되어야 합니다.
